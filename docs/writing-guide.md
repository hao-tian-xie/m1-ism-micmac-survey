# 问卷文案怎么写

这次修订参考了 Anthropic Engineering 的20篇完整文章，并逐图查看了5篇文章中的12张图。学习记录包括语言统计、逐篇结构标注、图文分析及写作规则，保存在项目外层的 `reports/m1-survey-writing/anthropic/`。

以下规则用于简体、繁体和英文问卷。它们来自对文章的分析，并结合了本问卷的访谈任务。

## 先写清要判断什么

页面先提出当前问题，再解释作答方式。例如，“改善这项工作，会直接帮助以下哪些工作？”后面紧接逐项回答的规则。来源与目标按参与者正在做的事来解释：需要改善的是来源，可能得到帮助的是目标。

这种先定义、再使用术语的顺序，可参考 [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) 和 [Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)。

## 把步骤、原因和结果放在一起

每项来源任务按“先回想 → 逐项判断 → 确认”组织。按钮写出下一步动作；会更改回答的操作，要在旁边说明作用范围。

例如，批量按钮旁写明“仅更新本页标为‘稍后检查’的项目，保留已有的其他判断”。选择完全经过中间工作的路径时，旁边说明来源到目标的直接判断会记为“无明确直接帮助”。

[Writing effective tools for agents](https://www.anthropic.com/research/writing-tools-for-agents) 用具体输入、输出和错误示例解释接口；本问卷把同样的解释顺序用于选择和操作结果。

## 让例子解释一个具体问题

每张管理卡先给简短定义。展开后，分别查看物流例子、判断范围与相邻议题，以及完整 ESRS 原文。介绍页中的箭头解释方向，旁边的文字说明这条箭头怎样记录。

[Managed Agents](https://www.anthropic.com/research/managed-agents) 在解释组件时保留一致的名称，并用图表说明它们的关系；[Agent Skills](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills) 按读者需要逐层展开细节。本问卷沿用这个层次，保留现有字体、白底和酒红色强调。

## 同一状态始终用同一个名字

| 页面回答 | 它记录的内容 |
| --- | --- |
| 有直接帮助 | 已判断来源会直接帮助目标。 |
| 无明确直接帮助 | 已查看目标，未发现明确的直接帮助。 |
| 无法判断 | 当前经验或信息不足。 |
| 稍后检查 | 尚未查看，保留为未判断。 |

这四种含义应同时出现在选项解释、任务摘要、回顾与后台。反方向单独询问，问题中写出来源和目标的名称。

## 三种语言按意思核对

先核对谁做什么，再核对范围、条件、否定和完成状态。简体与繁体使用当地自然表达；英文使用直接的动作句。保留全部数字、字数限制、稳定 ID 和标准原文。

七道业务经验问题已逐题审读，继续保留原文，以便按原题意作答和查看历史记录。它们周围的填写提示、隐私说明、导航和提交反馈按本轮规则整理。

## 最后做一次语言清理

按 shuorenhua 检查赘语、翻译腔和重复解释。按用户给定的标准删除防御性文字：一句话如果只用于预防批评，就删除；如果交代判断条件、记录含义或下一步动作，就保留其有效信息。
