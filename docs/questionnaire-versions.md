## 访谈与分配

保留原38项题库，环境19项、社会12项、治理7项。每个来源任务仍提供其余37个目标，允许跨领域选择。判断对象是这些 ESRS 议题背后的实际管理活动，原始名称、完整定义、ESRS 来源、类别与 ID 不改写。

默认分配方案 `vt3-balanced-12-v1` 提供01–10共10个题组，每组12项来源任务。题库按类别比例穿插排序，再循环分配120次任务；每个来源在计划中出现3或4次。研究者可将10个题组分别交给10名独立专家，并通过链接中的 `?batch=1` 等参数预填题组。受访者可在本组中选一项熟悉工作先做，其余任务仍全部保留；作答开始后不允许直接换组。

这是当前问卷采用的任务计划，不是文献规定的样本数，也不保证已经得到每项3次有效判断。未完成任务、无法判断、重复专家及实际分组覆盖仍需研究者核查。新增或调整题库后，应按当时的题库重新检查分配覆盖。

原有7道业务经验与遗漏问题全部保留。选填的业务经验题可在访谈中展开补充；重要、不清楚或跨领域的联系可说明一条机制，不要求每条关系都解释。每项来源最多记录一条解释，其他关键关系可在访谈记录中补充。预计访谈30–45分钟，具体时长按实际情况调整。

## 关系与未判断

| 输入 | 保存规则 |
| --- | --- |
| 已勾选目标 | 来源 → 目标记为 `1 / support`。 |
| 分组全部检查完，目标未勾选 | 记为 `0 / no_support`，含义为本次判断中无明确促进关系。 |
| 其余目标不熟悉、无法判断 | 未勾选目标记为 `null / unable`，保留本组已确认的正向选择。 |
| 分组尚未检查完 | 未勾选目标记为 `null / unreviewed`，保留本组已确认的正向选择。 |
| 来源任务未分配，且没有单独反向追问 | 记为 `null / unassigned`。 |
| 整项来源无法判断 | 清除本题目标和解释；全部外向判断为 `null / unable`。 |
| 单独反向追问 | 单独保存目标 → 来源的判断；没有追问就不添加反向关系。若与已有明确判断冲突，需返回核对。 |

分组检查状态与整题回答状态分别记录。“已检查部分没有明确促进关系”至少需要一个全部检查完的分组；其他未判断部分仍为空值。自我关系不提问，直接矩阵对角线按既有约定为0，初始含自达关系的矩阵对角线为1；对角线不计入判断覆盖。

## 数据与兼容

- 以 `protocolVersion: vt3`、`wordingVersion: vt3-20261023` 区分新版语义，原有 `factorVersion`、配置修订与稳定议题 ID 保留。
- 保存 `assignment`、实际 `presentationOrder`、来源级 `sourceSelections`、分组检查状态、可选解释与反向回答。
- 服务器从已验证的来源记录生成完整方向矩阵、状态矩阵与配对行。客户端可省略这些派生数组，减少传输体积；若提交了派生数组，必须与来源记录完全一致。
- `judgmentStatusMatrix` 区分支持、无明确支持、无法判断、尚未检查、未分配。SSIM 的 V/A/X/O 只在两个方向均有明确0/1判断时编码；任一方向未判断，`relation` 保留为空值，单方向已有判断仍保留。
- `progress` 的单位为 `source-tasks`，完成12项任务包含明确记录的“无法判断”，不表示38×37个方向均已完成判断。
- 后台详情及 CSV 保留方向状态、解释与题组。CSV 的 `source_tasks_json` 仅在每份答卷第一行输出，避免重复整份来源记录；JSON 保留完整字段。
- 原配置修订0的题库与问题定义保持原样。vt3 对原7道问题使用单独记录的三语措辞版本；后台按协议版本显示实际呈现的措辞。管理员新增或修改的配置仍按其独立修订和问题版本呈现。
- 旧协议的完整答卷继续按原有规则验证和读取。vt3 不把不完整个人判断生成个人议题排名，也不把它当作完整行业 ISM/MICMAC 结果。多专家汇总时，应按实际已判断的方向建立证据和共识，不能将空值补成0。
